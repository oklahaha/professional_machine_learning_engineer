    2. What is Data? Objects & Attributes

    Slide 15 先定義 structured data：一堆 objects，每個 object 用一組 attributes / features 嚟描述。可以想像成一個表格：

    • 每一 row = 一個 object (又叫 record, point, case, sample, entity, instance)。
    • 每一 column = 一個 attribute / feature。

    Slide 用咗兩個例子：

    Book No.TitleAuthorStudent IDHeight (cm)Weight (kg)
    001Data MiningJohn00117562
    002RobotsEdward00217965
    003ComputerDan00316860
    004MathematicsMary00418159

    左邊每本書係一個 object，attributes 係 Book No. / Title / Author；右邊每個學生係 object，attributes 係 Student ID / Height / Weight。

    💡 直覺理解

    之後 Week 4 學 pandas 時，DataFrame 就正正係呢個 object × attribute 嘅表：row = object (由 index 標示)，column = attribute (由 columns 標示)。所以呢個概念係成科嘅基礎。

    import pandas as pd
# 用 slide 15 右邊個例子建一個 DataFrame：每 row 係一個 object，每 column 係一個 attribute
students = pd.DataFrame({
    "Student ID": ["001", "002", "003", "004"],
    "Height (cm)": [175, 179, 168, 181],
    "Weight (kg)": [62, 65, 60, 59],
})
print(students.shape)   # (4, 3) → 4 個 objects，3 個 attributes
    🔗 跨科連繫

    COM6004 Data Mining Chapter 1–2 (Tan et al.) 用一模一樣嘅講法：data set = collection of data objects，object 由 attributes 描述。COM6002 嘅 relational model 就叫 tuple / row 同 attribute / column。

    3. Types of Attributes

    Exam Slide 16 把 attributes 分成兩大類，每類再細分：

    大類細分特點Slide 例子
    CategoricalNominal只係名稱 / 標籤，no order or comparisoneye color, zip codes, words
    Ordinal有次序 (order)，但兩級之間嘅「距離」not comparable (唔可以計差幾多)rankings (good, fair, bad)、height in {tall, medium, short}
    NumericalDiscrete可數嘅值 (counts)counts
    Continuous可以喺一個範圍內取任何實數值temperature, length, height in cm, weight in kg
    Special case: Binary只有兩個值yes/no, exists/not exists
    ⭐ 考試重點

    典型題目：「Classify the following attributes: eye color, ranking (good/fair/bad), number of children, body temperature, zip code, pass/fail.」

    • eye color → Categorical, Nominal
    • ranking good/fair/bad → Categorical, Ordinal
    • number of children → Numerical, Discrete
    • body temperature → Numerical, Continuous
    • zip code → Categorical, Nominal (雖然係數字，但計平均冇意義！)
    • pass/fail → Binary
    ⚠️ 常見錯誤 / 易混淆
    • 「睇落係數字」唔等於 Numerical。 Zip code、Student ID、電話號碼都係 Categorical (Nominal) — 判斷方法：加減乘除或者計平均有冇意義？
    • 同一樣嘢可以有唔同 type：height in cm 係 Continuous，但 height in {tall, medium, short} 係 Ordinal。type 取決於點樣量度 / 記錄。
    • Ordinal 「有次序但唔可以比較距離」：good > fair > bad，但「good − fair」同「fair − bad」係咪一樣？冇意義。
    • Slide 將 dates, time 列為 Numerical 例子。
    🔗 跨科連繫

    COM6004 Ch.2 會再細分成 Nominal / Ordinal / Interval / Ratio 四種 (按支援嘅 operations：=, <, +, ×)。COM6005 Module 1 亦會分 qualitative vs quantitative variables。pandas 入面，Categorical 通常用 object / string / category dtype，Numerical 用 int64 / float64，Binary 用 bool (見 Week 4)。

    import pandas as pd
df = pd.DataFrame({
    "eye_color": ["blue", "brown", "green"],          # Nominal
    "rating": ["good", "bad", "fair"],                # Ordinal
    "n_children": [0, 2, 1],                          # Discrete
    "temperature": [36.5, 37.2, 36.8],                # Continuous
    "smoker": [True, False, False],                   # Binary
})
# Ordinal 可以用 ordered categorical 表示次序
df["rating"] = pd.Categorical(df["rating"], categories=["bad", "fair", "good"], ordered=True)
print(df.dtypes)
print(df["rating"] > "fair")   # 有次序先可以比較大細

    4. What is Data Analytics?

    Slide 17：Data Analytics = Knowledge discovery from data! Data 本身蘊含 value 同 knowledge，analytics 就係把佢挖出嚟。

    🖼️ 圖片內容

    Slide 17 嘅 DIKW pyramid 係圖片，文字擷取不到；請對照原 slide 第 17 頁。

    一般嚟講 DIKW 指 Data → Information → Knowledge → Wisdom 由下而上嘅金字塔：raw data (例如一堆 sales 數字) 經整理變成 information (「上個月 A 店賣咗 500 件」)，再歸納成 knowledge (「下雨天 A 店銷量會跌」)，最後變成可以指導行動嘅 wisdom (「天氣預報落雨就減少 A 店入貨」)。

    Exam Slide 18：Given lots of data，我哋想發現嘅 patterns / models 要符合四個條件：

    條件Slide 定義解釋
    Validhold on new data with some certainty唔係只喺手頭 data 成立 (唔係 overfitting / 巧合)，放落新 data 都大致成立。
    Usefulshould be possible to act on the item (e.g., making decisions)要可以據此採取行動。
    Unexpectednon-obvious to the system如果係人人都知嘅嘢 (「買麵包嘅人都會買嘢」) 就冇價值。
    Understandablehumans should be able to interpret the pattern人要睇得明、解釋得到。

    Slide 用咗經典例子 “Diaper and Beer!”：超市發現買尿片 (diaper) 嘅顧客好多時都會買啤酒 (傳說係爸爸被叫去買尿片，順手買啤酒)。呢個 pattern 係 unexpected (直覺上兩者冇關)、useful (可以將兩樣貨擺近啲 / 一齊做推廣)、understandable (解釋得到)、亦需要 valid (喺新交易都成立)。

    🔗 跨科連繫

    Diaper & Beer 係 association rule mining 嘅經典例子；COM6004 Data Mining 嘅 Ch.1 都會用 knowledge discovery (KDD) 呢個框架。

    6. Characteristics of Big Data: the 5 V's

    Exam Slide 20 列出 Big Data 嘅 5 V's：

    VSlide 細項意思 & 例子
    Volume—數據量巨大 (TB、PB 級)，單一部機存唔落 / 處理唔到。例：Facebook 每日上載嘅相。
    VelocityIncoming Stream；Real-time Analytic數據產生同需要處理嘅速度好快，係連續流入嘅 stream，需要 real-time analytics。例：股票報價、信用卡 fraud detection。
    VarietySocial Network (Graph)；Tweet Message (Text, Image, Video)；Click Log (Relational)數據格式多樣：graph、text、image、video、relational table 等。
    VeracityAccuracy數據嘅準確性 / 可信度：有 noise、錯誤、missing values、假資料。
    Value—最終要由數據提煉出商業 / 社會價值，否則收集再多都冇用。
    🖼️ 圖片內容

    Slide 20 右邊嘅 5V 圖 (Big-Data-5V.gif) 係圖片，文字擷取不到；請對照原 slide 第 20 頁。

    ⭐ 考試重點

    要背：Volume, Velocity, Variety, Veracity, Value。常見題型：「Give a scenario and identify which V is the main challenge」，例如：

    • Twitter 每秒幾千條 tweet 要即時分析情緒 → Velocity (stream, real-time)。
    • 同時分析 tweet 文字、相片、用戶關係網 → Variety (text / image / graph)。
    • 傳感器有時壞咗報錯數 → Veracity (accuracy)。
    💡 直覺理解

    Week 5–7 嘅 Data cleaning (處理 missing values、duplicates、錯誤數據) 就係針對 Veracity；pandas 處理多種檔案格式 (csv / excel / json / xml，見 Week 4) 就係面對 Variety。

    🔗 跨科連繫

    COM6002 Big Data Management 講 4 V's (通常係 Volume, Velocity, Variety, Veracity) 同 structured / semi-structured / unstructured data、scale up vs scale out；COM6001 多咗 Value。考試時跟返該科 slides 嘅版本作答。

    7. Data Analytic Tasks: Descriptive vs Predictive

    Exam Slide 21 將 analytic tasks 分兩類：

    Descriptive methodsPredictive methods
    定義 (slide)Find human-interpretable patterns that describe the dataUse some variables to predict unknown or future values of other variables
    Method 例子Clustering, ClassificationRecommendation systems (Amazon, Google Play Store)
    Application 例子Medical diagnose (use Classification)Customer relationship management (CRM) systems
    Case studyJohn Snow cholera map (slide 22)；Gapminder (slide 23)Google Flu Trends (slide 24)
    ⚠️ 易混淆

    本科 slide 把 Classification 放喺 Descriptive 例子。但 COM6004 (Tan et al.) 通常將 Classification 歸為 Predictive task (用 attributes 預測 class label)，Clustering / association rules 先係 Descriptive。COM6001 考試跟本 slide 作答，但可以補充一句「classification models can also be used for prediction」，兩邊都唔錯。

    7.1 Clustering example: John Snow & Cholera (slide 22)

    Clustering = Group similar data together. 十九世紀倫敦爆發霍亂 (Cholera)，醫生 John Snow 將每個病例畫喺城市地圖上，發現病例圍繞住某幾個路口聚集 (cluster) — 呢啲路口就係受污染嘅水井位置。住近污染水井嘅人病咗，住近乾淨水井嘅人冇事。「Without the ability to cluster the data, the cause of Cholera would not have been discovered.」

    💡 直覺理解

    呢個例子顯示：clustering 唔一定要電腦，核心係「把相似 (位置接近) 嘅 data points 歸成一組，再睇每組有咩共同原因」。而且全程冇用到 label (冇人預先話你邊個井有問題) — 即係 unsupervised。

    8. The CRISP-DM Process & Data Science Processes

    Exam Slide 25：CRISP-DM (CRoss Industry Standard Process for Data Mining) 係一個 process model，作為 data science process 嘅基礎。六個步驟：

    1. Business Understanding — 釐清商業目標同問題 (要解決咩？成功點樣衡量？)。
    2. Data Understanding — 收集同初步探索 data (有咩 attributes？質素點？)。
    3. Prepare Data — cleaning、轉換、合併、feature engineering (本科 Week 4–7 重點)。
    4. Data Modeling — 揀同訓練 model (clustering、classification、regression…)。
    5. Evaluate the Results — 睇 model 結果係咪達到 business objectives。
    6. Deploy — 將結果 / model 投入實際使用。
    ⭐ 考試重點

    記住次序同名稱：Business Understanding → Data Understanding → Prepare Data → Modeling → Evaluation → Deployment。CRISP-DM 唔係一條直線：Business ↔ Data Understanding 之間會來回，Evaluation 唔滿意會返去 Business Understanding 重新開始 (iterative)。

    🖼️ 圖片內容

    Slide 25 嘅 CRISP-DM 循環圖同 slide 26 嘅「Data Science Processes」流程圖 (來源 towardsdatascience) 都係圖片，文字擷取不到；請對照原 slide 第 25–26 頁。上面「iterative / 來回」係 CRISP-DM 嘅一般描述，並非由圖片擷取。

    💡 直覺理解

    對應本科內容：Week 4 data manipulation (載入、合併) + Week 5–7 data cleaning / feature engineering = Prepare Data；Week 8–9 EDA = Data Understanding；Week 10 visualization 用於 Understanding 同 presenting results。實際做 project 時大部分時間 (常說 60–80%) 都花喺 Data Preparation。

    import pandas as pd
# 一個極簡 CRISP-DM 流程示意 (假設有 sales.csv)
# 1. Business Understanding: 想知邊類產品銷量最好
# 2. Data Understanding
df = pd.read_csv("sales.csv")
print(df.info())
# 3. Prepare Data
df = df.dropna(subset=["category", "amount"])
# 4. Modeling (此處只用簡單 aggregation 代替)
result = df.groupby("category")["amount"].sum().sort_values(ascending=False)
# 5. Evaluate: 結果有冇回答到問題？
print(result.head())
# 6. Deploy: 例如輸出報告
result.to_csv("top_categories.csv")

    自我測驗 Self-test

    Q1. 一個 object 喺 structured data 入面仲有咩其他叫法？Attributes 又叫咩？

    Object 又叫 record, point, case, sample, entity, instance；attributes 又叫 features。喺表格中 object = row，attribute = column。

    Q2. 將以下 attributes 分類：(a) zip code (b) customer satisfaction {low, medium, high} (c) number of purchases (d) weight in kg (e) has_membership {yes, no}

    (a) Categorical – Nominal (數字但冇次序 / 計算意義)；(b) Categorical – Ordinal (有次序，但距離不可比較)；(c) Numerical – Discrete (counts)；(d) Numerical – Continuous；(e) Binary (special case)。

    Q3. Nominal 同 Ordinal 有咩分別？各舉一例。

    Nominal：只係名稱，no order or comparison，例如 eye color。Ordinal：有次序，但各級之間嘅距離 not comparable，例如 rankings (good, fair, bad)。

    Q4. 列出 Big Data 嘅 5 V's，並指出「一間銀行要喺 0.1 秒內判斷每宗信用卡交易是否 fraud」主要係邊個 V？

    Volume, Velocity, Variety, Veracity, Value。信用卡 fraud detection 要處理不斷流入嘅 transaction stream 並 real-time 分析 → 主要係 Velocity。

    Q5. Data analytics 發現嘅 pattern 要符合邊四個條件？用 “Diaper and Beer” 解釋其中兩個。

    Valid, Useful, Unexpected, Understandable。Unexpected：尿片同啤酒表面無關，係 non-obvious 嘅發現；Useful：超市可以將兩樣貨擺近 / 做 bundle promotion，即可據此做決策 (act on it)。

    Q6. Descriptive 同 Predictive methods 嘅分別？John Snow 嘅 cholera map 同 Google Flu Trends 各屬邊類？

    Descriptive：find human-interpretable patterns that describe the data。Predictive：use some variables to predict unknown or future values of other variables。John Snow → Descriptive (clustering 病例位置找出污染水井)；Google Flu Trends → Predictive (用 flu-related 搜尋頻率預測流感人數)。

    Q7. 按次序寫出 CRISP-DM 六個步驟。Data cleaning 屬於邊一步？

    1 Business Understanding → 2 Data Understanding → 3 Prepare Data → 4 Data Modeling → 5 Evaluate the Results → 6 Deploy。Data cleaning 屬於第 3 步 Prepare Data。
