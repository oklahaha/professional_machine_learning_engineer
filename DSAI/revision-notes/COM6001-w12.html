    Big Data Frameworks & Ethics

    🎯 本講重點 (Learning outcomes)

    • 認識 CPU、Memory (RAM)、Storage (SSD)、Network、GPU 嘅角色同速度差距，明白點解 data 大咗之後 bottleneck 由 CPU compute 變成 storage / network I/O。
    • 判斷幾時用一部電腦就夠、幾時要用 distributed computing（file 遠大過 memory，或者 process 好複雜，例如 DNN training）。
    • 分清 distributed computing（每個 CPU 有自己 memory，經 network 連接）同 parallel computing（多個 CPU 共用同一個 memory）。
    • Distributed data processing 嘅 4 大 challenges：Partitioning、Communication overhead、Fault tolerance、Consistency & reproducibility。
    • Big data system 4 個 main components；Hadoop vs Spark 嘅主要分別（memory 用法）。
    • Data ethics：5 Cs、distributed computing 特有嘅 ethical concerns、(Gen)AI 喺 development / usage 階段嘅 ethical challenges 同 mitigation。

    ⭐ 考試必溫 Top-5

    1. Data > RAM 時發生乜事（program 要將 data 讀入 memory）：OS swapping / paging，CPU 喺度 I/O wait，真正用嚟計數嘅時間好少 → 考慮 distributed。
    2. Distributed vs Parallel：own memory + network vs shared memory（slide 14 in-class exercise：C、D、E 正確）。
    3. 4 key challenges＋每個 platform 點處理（data skew、send only summaries、redo failed part、controlled order）。
    4. Hadoop vs Spark：Hadoop 將 intermediate results 寫落 disk；Spark 盡量 keep in memory → 通常更快。
    5. 5 Cs（Consent、Clarity、Consistency、Control、Consequences）同 distributed / GenAI ethical issues。

    規格數字點讀（slide 5）

    Spec意思

    2. CPU、RAM、SSD、Network 嘅速度差距（slides 6–8）

    Exam Slide 6（key）：CPU is fast, storage is slow。CPU 以 nanoseconds 運作；RAM 慢啲但仍然夠快；SSD 比 RAM 慢好多。

    情況發生乜事結果
    Data fits in RAMCPU 由 RAM 讀 data，連續計算High utilization、fast processing
    Data larger than RAM（program 要將 data 放入 memory）OS 開始喺 RAM 同 SSD 之間 swapping / paging；CPU 經常等 data 搬運（I/O wait）真正用嚟 computation 嘅時間少好多

    Slide 8 嘅圖（network delay）列出相對速度：

    Component相對速度（slide 8 圖）
    CPU（fastest）比 memory 快 200 倍
    Memory比 SSD 快 15 倍
    SSD比 network 快 20 倍
    Network（slowest）—

    即係由 network 攞同一份 data，比喺自己 storage / memory 處理慢好多。照圖嘅倍數乘埋，CPU 大約比 network 快 \(200 \times 15 \times 20 = 60{,}000\) 倍（只係由圖嘅數字推算嘅數量級）。

    ⭐ 考試重點
    • 速度排名：CPU > Memory > SSD > Network。
    • Data 大過 RAM → swapping / paging → CPU I/O wait → 慢。
    • Key message（slide 7）：When data gets large, bottlenecks shift from CPU compute to network and storage I/O.

    3. Case study I：你部電腦夠唔夠快？（slide 7）

    情境：每日 6000 篇新聞 × 200 bytes = 1.2 million bytes；CPU 2.5 GHz、8 GB RAM。任務：live character count。

    $$ \text{CPU throughput} = 2.5 \times 10^9 \times 8 = 20 \times 10^9 \text{ bytes/s} $$
    $$ \text{Time} = \frac{1.2 \times 10^6}{20 \times 10^9} = 6 \times 10^{-5}\ \text{s} $$

    1.2 MB 完全放得落 RAM，計算時間只係 \(6 \times 10^{-5}\) 秒（0.06 ms）。

    ⚠️ Slide 寫法

    Slide 寫「Time needed: 1.2e6 / 20e9 = 0.006%」。\(1.2 \times 10^6 / (20 \times 10^9) = 6 \times 10^{-5}\)，即 \(6 \times 10^{-5}\) 秒，等於一秒嘅 0.006%。考試寫答案時請寫單位「秒」，唔好只寫百分比。

    Reality：data 要先 fetch。RAM latency 約 100 ns（幾百個 CPU cycles）；SSD latency 更高（microseconds）。所以 runtime 通常由 data access 主導，唔係由 arithmetic 主導。

    4. Case study II & III：not-so-big vs big data（slides 9–11）

    Case II（slide 9）：4 GB 新聞 data、8 GB memory、1 × 2.5 GHz CPU，任務係 filter 所有關於 China 嘅新聞。Option 1：喺自己電腦用 Python program；Option 2：切開 data 分俾 12 個同事處理。

    4 GB < 8 GB RAM，成份 data 放得落 memory，所以 Option 1（一部電腦）就得；分俾 12 個人反而要額外搬 data（network 最慢）同協調。

    Exam Key consideration：I/O bottleneck（slide 10，key）：I/O 係 bottleneck，將 data 由 SSD 搬去 memory 會燒晒 CPU 嘅時間。It is a good idea to go distributed if your file is much larger than your memory.

    Slide 10 嘅圖標住「SSD — 8 GB」同「MEMORY — 10 MB」，圖旁邊冇額外文字解釋呢兩個數字；看來係示意 data 遠大過 memory 嘅情況。

    Case III（slide 11）：data 由 4 GB 增加到 200 GB，用同一個 Python program，一陣之後電腦冇反應。點解？

    1. It took too long to move data across the network
    2. The CPU couldn't load data quickly from memory
    3. The memory couldn't load data quickly from storage
    4. The CPU simply couldn't handle the larger data set
    5. The storage couldn't load data quickly from the network
    6. The CPU is too busy moving data around, no room for data analysis.
    ⭐ 參考答案（slide 冇印答案）

    C 最貼合 slide 6 嘅解釋：200 GB 遠大過 8 GB RAM，memory 要不停由 storage（SSD）搬 data 入嚟（swapping / paging），CPU 大部分時間喺 I/O wait。

    • A、E 錯：成個 program 喺一部電腦行，冇經 network。
    • B 錯：CPU 由 RAM 讀 data 係快嘅；問題係 RAM 放唔落。
    • D 錯：CPU 處理能力冇問題（Case I 證明 CPU 好快）。
    • F 同 slide 10「Moving data from SSD to memory burns out your CPU's time」嘅講法相近；如果題目係 multiple-select，F 可能都被接受。但準確講 CPU 係喺度等 data（I/O wait），唔係「忙住計」。

    5. 點解唔一直用一部電腦？（slide 12）

    Exam Data 增長時會撞到 4 種 limits：

    Limit意思
    Storage limitDataset 一隻 disk 放唔落
    Memory limitData load 唔入 RAM
    Time limitProcessing 太耐
    Reliability limit一部機壞咗，成個 job 停晒
    ⭐ Distributed computing 幾時需要？
    • 有 big data 要處理：例如由 200 GB data 抽出所有 China-related news。
    • Data 唔算大，但 process 好 sophisticated：例如 train 一個有 millions of parameters 嘅 DNN。

    Revision.pdf 問法：「When to use one PC or a group of PC?」→ data 放得落 memory 而 process 簡單：一部 PC；data 遠大過 memory，或者 process 好重：一組 PC（distributed）。

    7. Big Data Eco-System：4 個 key challenges（slides 15–19）

    Big data 嘅典型工作：有大量 records、logs、news、blogs、videos，要 summarize 結果（sorting、counting、searching、filtering…）。分散去多部機做，就會有以下 4 個 challenges（每張都係 key slide）：

    Challenge要考慮嘅問題Platforms 點做Examples
    #1 Partitioning按 rows？time？user？region？切；partitions 平唔平衡？會唔會有一部機多好多工作（data skew）？Partition 得差 → performance 跌將 data 切成好多細 chunks，送去好多部機Hadoop MapReduce、Spark、BigQuery、Snowflake
    #2 Communication overhead經 network 搬 data；synchronize intermediate results；coordinate task completion。太多 communication 會抵銷速度增益盡量喺 data 所在地處理，只送較細嘅 summariesMapReduce（combine step）、Spark（keeps data in memory）、cloud warehouses（smart query planning）
    #3 Fault toleranceDistributed systems 入面 failure 係正常事；要偵測 failed tasks、重跑 lost work、由 partial progress recover。目標：部分 nodes 壞咗系統都繼續偵測 failure，自動只重做失敗嗰部分MapReduce、Spark、AWS / GCP / Azure managed services
    #4 Consistency & reproducibility風險：execution order 唔同、duplicate processing、漏咗 late-arriving data。要小心設計先有 reliable、repeatable outputs用 controlled order 行 tasks、track progress、allow safe restartSpark / MapReduce（processing）、Airflow / Prefect（pipeline scheduling）、Kafka-based systems（continuous data）
    💡 直覺理解

    想像 12 個同事幫你 filter 新聞：(1) 點分工先公平（有人分到多十倍就要等佢）；(2) 每個人做完只交「結果」而唔係成疊報紙返嚟；(3) 有人病咗，只將佢嗰份重新分配；(4) 確保冇人重複做同一份、冇漏咗遲到嘅報紙，再做一次結果都一樣。

    ⚠️ 易混淆

    Data skew 係 Partitioning 嘅問題；「send only smaller summaries」係解決 Communication overhead；「redo only the failed part」係 Fault tolerance；「controlled order、safe restart」係 Consistency & reproducibility。MC 題好可能俾一個描述叫你配對 challenge。

    8. Main components、Hadoop vs Spark（slides 20–21）

    Exam Big data system 嘅 4 個 main components（slide 20，key）：

    1. The common utilities
    2. Data storage
    3. Job scheduler
    4. Data processing

    Slide 20 只用 icon 列出呢 4 個名，冇逐個解釋。一般理解：common utilities 係各部分共用嘅 libraries / tools；data storage 負責將 data 分散儲存喺多部機；job scheduler 負責分配同協調 tasks 同 resources；data processing 負責實際計算。以 Hadoop 為例，分別對應 Hadoop Common、HDFS、YARN、MapReduce（呢個對應係課外補充，slide 冇寫）。

    ⭐ Hadoop vs Spark
    HadoopSpark
    年代較舊，但仍有好多公司用較新
    Intermediate results寫落 disk盡量 keep in memory
    速度較慢（disk I/O 多）好多 use cases 更快

    兩者都係 big data storage 同 data analysis 嘅 major frameworks。主要分別係點用 memory。

    💡 點解 memory 決定速度

    返去 §2：memory 比 SSD 快約 15 倍。Hadoop 每一步做完都將中間結果寫落 disk，下一步再讀返；Spark 將中間結果留喺 RAM，省咗好多 disk I/O，所以同一個多步驟 job 通常快好多。

    Trade-offs（slide 21）

    BenefitsCosts
    Larger-than-memory processingMore system complexity
    Faster runtime（for large workloads）More debugging difficulty
    Better reliability at scaleHigher infrastructure / operation cost
    📝 Not required for exam

    Slide 21 嘅 Rule of Thumb 明確寫 not required for exam：Historical / batch big data → Spark（或 Hadoop legacy）；Real-time streams → Kafka + Flink / Spark Streaming；SQL-first analytics → Warehouse 或 Trino / Presto；Need less ops → Managed cloud platforms。

    9. Ethics when building data products：5 Cs（slides 30–32）

    我哋要嘅唔只係有用、或者商業上可行嘅 product，而係用 data 合乎道德同負責任嘅 product。The Five C's 係五個 framing guidelines。

    ⭐ 5 Cs（slide 32，key）
    C意思
    Consent就「收集咩 data、點用」達成協議，建立 trust
    Clarity清楚知道自己 consent 緊乜
    ConsistencyTrust 需要長期一致（今日承諾點用，聽日都係咁用）
    Control (and transparency)User 可唔可以控制 service 點用佢嘅 data？
    Consequences (and harms)收集嘅 data 會唔會對個人或群體造成傷害？
    ⚠️ 易混淆

    Consent 係「有冇同意」；Clarity 係「同意嘅內容係咪清楚」。例如一份 50 頁、用法律術語寫嘅 privacy policy，就算 user 撳咗「同意」（有 Consent），都欠 Clarity。

    10. Distributed computing 嘅 ethical concerns（slide 33）

    Exam Revision.pdf 列明要識「Special ethic issues with distributed computing」：

    Concern具體問題
    Data PrivacyIncreased exposure：data 分散喺多個 nodes 儲存同處理，較易被未授權存取或 breach。Data sharing：cluster 可能涉及多個 entities，誰可以接觸 sensitive information 成疑問。
    Data SecurityComplexity of security：clustered system 架構較複雜，會帶來 standalone system 冇嘅 vulnerabilities。Inter-node communication：nodes 之間傳送嘅 data 如果冇保護好，可能被截取或竄改。
    Accountability & ResponsibilityDistributed responsibility：出事時難以確定邊個負責。Lack of oversight：分散嘅特性可能令 data handling 缺乏足夠監督。
    Bias & FairnessData aggregation effects：data sources 唔具代表性時，clustering / aggregation 會放大 bias。Algorithmic bias：clustered environment 用嘅 algorithms 可能延續或加劇既有 bias。

    12. Mitigation plans（slides 37–38）

    單靠技術方案唔夠，ethical practice 需要 multi-faceted approach：

    類別方法
    Technical mitigationsExplainable AI (XAI)：令 model decisions 更 interpretable。Bias auditing：deployment 前做 fairness tests 同 metrics（例如 disaggregated error analysis，即按 group 分開睇 error rate）。Differential privacy：正式嘅數學 framework：限制加入或移除任何一個人嘅 data 對結果嘅影響，從而限制可以推斷到單一個人嘅資料（係 bound，唔係完全唔洩露）。Provenance tracking：model cards、datasheets for datasets，記錄 model 同 data 嘅來源、用途同 limitations。
    Governance & processEthics review boards（類似 research 嘅 IRB）；Red teaming：release 前主動嘗試「搞爛」系統或搵出 harmful uses；Clear lines of accountability。
    The human factorDiverse teams：同質團隊易有盲點；Ethics education：唔係 soft skill，而係 core engineering requirement。

    自我測驗 Self-test

    Q1. 一部 2.5 GHz 64-bit CPU 每秒最多處理幾多 bytes？處理 1.2 MB 要幾耐？

    \(2.5 \times 10^9 \times 8 = 2 \times 10^{10}\) bytes/s。時間 = \(1.2 \times 10^6 / (2 \times 10^{10}) = 6 \times 10^{-5}\) 秒（0.06 ms）。但現實中 runtime 主要由 data access（RAM latency ≈ 100 ns、SSD 更慢）決定。

    Q2. 將 CPU、SSD、Network、Memory 由快到慢排列。

    CPU > Memory > SSD > Network（slide 8：CPU 比 memory 快 200×，memory 比 SSD 快 15×，SSD 比 network 快 20×）。

    Q3. 8 GB RAM 嘅電腦處理 4 GB data 同 200 GB data，分別應該點做？點解？

    4 GB：放得落 RAM，用一部電腦 Python 處理就得；分散反而多咗 network 搬運同協調成本。200 GB：遠大過 RAM，會 swapping / paging，CPU 長期 I/O wait（Case III 答案 C）→ 應該 go distributed。

    Q4. Data 唔大，但點解有時都要用 distributed computing？

    當 process 好 sophisticated，例如 train 一個有 millions of parameters 嘅 deep neural network，計算量大（time limit），所以都需要 distributed computing。

    Q5. Distributed computing 同 parallel computing 喺 memory 上有乜分別？

    Distributed：每個 CPU 有自己 memory，machines 經 network 連接。Parallel（OpenMP / OpenCL）：多個 CPU 共用同一個 memory。Slide 14 正確嘅 statements 係 C、D、E。

    Q6. 「一部機分到嘅 data 多過其他機好多倍，結果大家都要等佢」屬於邊個 challenge？Platforms 點處理？

    Challenge #1 Partitioning（data skew）。Platforms 將 data 切成好多細 chunks 分俾好多部機（Hadoop MapReduce、Spark、BigQuery、Snowflake）。

    Q7. Spark 點解通常比 Hadoop 快？

    Hadoop 將 intermediate results 寫落 disk；Spark 盡量將 data 留喺 memory。Memory 比 disk / SSD 快好多，所以多步驟 job 嘅 I/O 少好多。

    Q8. 列出 big data system 嘅 4 個 main components。

    The common utilities、Data storage、Job scheduler、Data processing。

    Q9. 一個 app 喺 user 同意後收集位置 data，一年後改咗用途賣俾廣告商而冇通知。違反咗 5 Cs 邊幾個？

    主要係 Consistency（用途前後唔一致）同 Consent / Clarity（user 冇同意新用途，亦唔清楚）；user 冇得揀亦違反 Control (and transparency)；位置 data 可能被濫用，涉及 Consequences (and harms)。

    Q10. 舉兩個 distributed computing 特有嘅 ethical concerns，同兩個 GenAI usage stage 嘅 challenges。

    Distributed：Data privacy（多 nodes → increased exposure、data sharing）、Data security（inter-node communication 可被截取）、Accountability（distributed responsibility）、Bias（aggregation effects）。GenAI usage：privacy erosion & surveillance、accountability & liability、environmental impact、over-reliance / automation bias、IP / plagiarism、malicious use。

    • CPU = brain；Memory = short-term quick storage；SSD = long-term safe storage；Network = connection；GPU = massively parallel processor。

    • 速度：CPU (200×) > Memory (15×) > SSD (20×) > Network。
    • Data > RAM → swapping / paging → I/O wait；bottleneck 由 CPU 轉去 storage / network I/O。
    • File 遠大過 memory → go distributed；或者 process 好複雜（DNN）。4 limits：storage、memory、time、reliability。
    • Distributed：own memory + network；Parallel：shared memory。
    • 4 challenges：Partitioning（data skew）、Communication overhead（send summaries）、Fault tolerance（redo failed part）、Consistency & reproducibility（controlled order、safe restart）。
    • 4 components：common utilities、data storage、job scheduler、data processing。
    • Hadoop 寫 disk；Spark keep in memory → 更快。
    • Benefits：larger-than-memory、faster、reliable；Costs：complexity、debugging、cost。
    • 5 Cs：Consent、Clarity、Consistency、Control、Consequences。
