    MongoDB: Document Database

    🎯 本講重點 (Learning outcomes)

    • MongoDB 係 document-based NoSQL database：dynamic schema、BASE（可設定達到 ACID）、horizontal scalability、programming friendly。
    • Terminology：Database → Collection → Document → Field（對應 RDBMS 嘅 Database → Table → Row → Column）。
    • Design decision：Embedding vs Referencing 同 rules of thumb；16 MB document limit。
    • Indexing（B+ tree、2dsphere、text、unique）同 _id（12-byte ObjectId）。
    • Distributed：Sharding（hashed vs ranged）、Replica set（primary / secondary、heartbeat、election）、write concern、read concern、architecture（router、config servers、shards）。
    • 8b（唔考）：JSON / BSON、pymongo CRUD、projection、query operators、aggregation pipeline（$match、$group、$lookup、$unwind…）。

    ⭐ 考試必溫 Top-5

    1. RDBMS vs MongoDB terminology 對照，同 dynamic schema 嘅意思。
    2. Embed vs reference 嘅 rules of thumb（一對一 / 一對多專屬 → embed；多對多 / 共用 / 無上限 → reference）。
    3. Hashed vs ranged sharding，同 slide 19 IM messages 例子點揀。
    4. Replica set：default 所有 reads / writes 去 primary；secondaries 做 backup & recovery；primary 壞咗就 elect 新 primary。

    1. MongoDB 係乜（8a slides 2–5）

    • A document-based database system，2007 年成立；db-engines.com ranking 嘅 Top-1 NoSQL database。
    • Dynamic schema：同一個 collection 入面嘅 documents 可以有唔同 fields 同 data types。
    • Initial design 跟 BASE 而唔係 ACID；而家可以透過某些 configurations 做到 ACID（但有 overheads）。
    • 易加 nodes / machines：horizontal scalability（scale out）。
    • Easy to use (in programming)。

    Python → SQL（SELECT）→ Parse the result → Use the data objects（要多學一種語言 SQL）Python → Data objects（直接攞到 objects）

    支援好多語言：Python、Node.js、C / C++ / C#、Go、Java、PHP、Ruby、Rust、Scala、Swift…。每種語言 syntax 稍有唔同，但用同一套 query framework：Find、Projection、Aggregate、Sort、Update。

    2. Data model 同 terminology（slides 6–9）

    RDBMS 要將學生資料拆兩個 tables（Student：ID、Name、Major；Result：ID、Module Code、Grade），MongoDB 可以將佢哋 consolidate 成一個 document，支援 hierarchical structure：

    {
  "Student ID": 101101,
  "Name": "Amy",
  "Major": "BBA",
  "Results": { "COM2006": "B", "COM2103": "A" }
}

    MongoDB 可以有多個 databases；一個 database 有多個 collections；一個 collection 有多個 documents；一個 document 有多個 fields。

    ⭐ Terminology comparison（slide 8）
    RDBMSMongoDB
    DatabaseDatabase
    TableCollection
    Record (Row)Document
    Attribute (Column)Field

    Exam Dynamic schema（slide 9）：以下兩個 documents 可以放喺同一個 collection：

    { "Student ID": 101101,    "Name": "Amy", "Major": "BBA", "Results": { "COM2006": "B", "COM2103": "A" } }
{ "Student ID": "s101102", "Name": "Bob", "Parents": ["Mary"], "Brothers": ["John"] }

    兩個分別：(1) Student ID 嘅 data type 唔同（number vs string）；(2) fields 嘅集合唔同。Document data 用 BSON format 定義（8b 講）。

    ⚠️ 易混淆

    Dynamic schema 唔等於「冇 schema」：application 仍然要知道 fields 點用。好處係 agile（改結構唔使 ALTER TABLE），代價係 data quality 要靠 application 控制（例如 ID 有時係 number 有時係 string，query 時要小心）。

    3. Design decision：Embedding vs Referencing（slides 10–11）

    EmbeddingReferencing
    將 data 放入 document 入面（Amy 嘅 Results 直接 nested）用一個 ID 指向其他 document(s)（Amy 一個 document；每科成績各自一個 document，用 Student ID 101101 連返）
    ⭐ Rules of thumb（slide 11，based on practice rather than theory）
    When to embed?When to reference?
    Child data 主要喺 parent 嘅 context 入面睇Child data 會獨立於 parent 被睇
    Child data 比較細、size 有上限（bounded）Child data 好大或者無上限（unbounded）
    One-to-one relationshipMany-to-many relationship
    One-to-many，而 child data 專屬於 parentChild data 被多個 parents 共用
    需要 fast reads（唔使 join）—

    MongoDB 一個 document 最大 16 MB，所以 unbounded child data（例如一個 user 嘅所有 messages）唔應該 embed。

    💡 例子

    學生 + 地址（一對一、細）→ embed。學生 + 成績（一對多、專屬、有上限）→ embed 得。學生 + 科目（many-to-many，科目資料畀好多學生共用）→ reference。Blog post + comments（可以無限增長）→ reference。

    4. Indexing 同 _id（slides 12–15）

    • Exam Indexing 用 B+ tree；改善 search time，代價係額外 storage 同 index maintenance。
    • Document 冇 index field 嘅值 → 一般（non-sparse）index 會用 null key 記錄（document 本身唔變；sparse index 就會跳過呢啲 documents）。
    • 可以設為 unique：reject index field 上嘅重複值。
    Index type用途
    1（asc）Ascending / -1（desc）Descending兩者都用 B+ tree，searching time 降到 \(O(\lg n)\)
    2dsphereMulti-dimensional search（地理位置）；reference：R-tree
    textText search；有專門 index structure，同 numeric data 唔同

    Slide 12 嘅圖係 MongoDB Compass 建立 index 嘅截圖；slide 13 右邊係揀 index type 嘅 dropdown（1 (asc)、-1 (desc)、2dsphere、text）。

    🔗 跨科連繫

    B+ tree、\(O(\lg n)\)、index 嘅 overhead 同 Week 3 RDBMS indexing 一樣（8b slide 19 嘅 revision questions：點解要 index？要幾多個？有冇 overhead？）。Text index ↔ Week 7 Elasticsearch inverted index。

    Exam Identifying document（slides 14–15）：每個 document 都有 system generated ID，field 名係 _id，自動產生、保證 unique（sharded collection 如果 _id 唔係 shard key，只保證每個 shard 內 unique）。

    _id 特點內容
    Data typeBSON ObjectId，12-byte identifier；睇落似 string，但唔係 string
    Composition頭 4 bytes：timestamp；之後 5 bytes：random value；最後 3 bytes：incrementing counter
    排序因為開頭係 timestamp，naturally sorted chronologically
    Mandatory每個 object 都必須有 _id；可以自己設其他 type（string / number）

    5. Sharding（slides 16–19）

    Exam Sharding：將 data partition 同分散到多個 nodes；持有部分 data 嘅 node 叫 shard。Partitioning method 係 deterministic，可以設定：揀 shard key（例如 creation datetime）同 sharding strategy。屬於 horizontal fragmentation（按 documents / rows 切）。

    Hashed shardingRanged sharding
    方法按 shard key 值嘅 hash value 分配 documents每個 chunk 負責一段 shard key 值嘅 range
    Slide 圖{x: 25}、{x: 26}、{x: 27} 經 hash function 後分去唔同 chunks（相鄰值唔會喺同一 chunk）相鄰嘅 key 值喺同一 chunk
    好處分佈平均，storage / write load 分散Range query 快（只需讀少數 chunks）
    壞處Range query 要問晒所有 shardsKey 單調遞增（例如時間）時，新 data 集中喺最後一個 chunk → hotspot
    ⭐ Discussion（slide 19）：邊種 sharding 好？

    情境：instant messaging software 嘅 messages；shard key fields：account ID、message datetime。

    • Goal 1：將 storage load 分散到多部機 → Hashed sharding。
    • Goal 2：fetch 用戶指定月份嘅 data → Ranged sharding，by (account, datetime)：同一 account 同一段時間嘅 messages 排埋一齊，喺一個或幾個相鄰 chunks，router 只需問持有嗰段 range 嘅 shards。

    Slide 17、18 嘅圖：hashed 圖顯示 {x: 25}、{x: 26}、{x: 27} 經 Hash Function 分去 Chunk 1–4 唔同位置；ranged 圖（slide 18）為 chunks 對應 key ranges 嘅示意圖，冇額外文字。

    🔗 跨科連繫

    Sharding ＝ Week 6 horizontal fragmentation；COM6001 Week 12 big data challenge #1 Partitioning（data skew = hotspot）。

    6. Replica set（slides 20–22）

    Exam Replication 提供 redundancy、提高 data availability；類似 Raft consensus。不同 database servers 有多份 copies，可以 tolerate 單一 server 嘅損失。Heartbeat：nodes 互相 ping，睇對方仲在唔在生。

    • Workload 唔會喺 replica set 嘅 nodes 之間分擔（default setting）：reads 同 writes always 去 primary。
    • Reads 可以設定去 secondary（例如 nearest secondary）。
    • Secondary nodes 用嚟 backup 同 recovery。
    • Primary 將 writes replicate 去 secondaries；視乎設定，可能唔會等 replication 完成先回覆 client（即 write concern）。
    • Node failure（slide 22）：primary 壞咗就 elect 一個新 primary。

    Slide 21 圖：Client Application → Driver；Writes 同 Reads 都去 Primary；Primary 以 Replication 箭咀連去兩個 Secondary。Slide 20、22 嘅 heartbeat / election 圖冇額外文字。

    ⚠️ 易混淆：Sharding vs Replica set
    ShardingReplica set
    目的Scalability：分散 data 同 workloadAvailability / fault tolerance：多份 copies
    每個 node 有部分 data全部 data（同一份嘅 copy）
    分擔 workload？✔✘（default 全部去 primary）

    實際系統兩者一齊用：每個 shard 本身係一個 replica set（slide 28）。

    📝 補充（同 Week 6 一致）

    Election 需要 voting members 嘅 majority；primary 如果聯絡唔到 majority 會 step down。所以 minority 嗰邊唔會繼續做 primary 接受 writes。

    7. Write concern 同 read concern（slides 23–27）

    Exam Write concern：要求 MongoDB 對 write operations 俾幾多程度嘅 acknowledgement。本質係 latency vs durability 嘅 trade-off。格式：{ w: <value>, j: <boolean>, wtimeout: <number> }。

    ⭐ 三種 write concern
    SettingBehaviourProsCons / Risk
    { w: 1 }
    Primary acknowledgment only（slide 寫 default）    		Primary 成功 apply write 就即刻回覆最快 write latencyPrimary 喺 replicate 之前壞咗 → failover 時 data 可能 lost
    { w: "majority" }
    Quorum-level durability    		要 majority 嘅 data-bearing members（primary + 足夠 secondaries）apply 咗先回覆最高 durability：data 保證 survive automatic failover要等 network replication → write latency 較高
    { j: true }
    Disk persistence    		寫入 on-disk journal 先 acknowledgeCrash 後可 recover（journal = write-ahead log，data file 未 flush 都救得返）要等 disk write

    Best practice：mission-critical data 用 w: "majority" + j: true。

    ⚠️ Default 版本差異

    Slide 24 話 w: 1 係 default setting，考試跟 slide 答。實際上 MongoDB 5.0 起，大部分 replica set 嘅 implicit default write concern 已改為 w: "majority"（有 arbiter 等特殊配置先例外）。

    Read concern（slide 27）：控制讀取 data 嘅 consistency 同 isolation。

    Setting意思
    local（default）回傳當前 member 嘅 state；可能未反映其他 members 嘅 writes；最快
    majority只回傳已被 majority members acknowledge 嘅 data；保證讀到嘅 data 係 durable（唔會因 failover 被 roll back）
    💡 直覺理解

    Write concern 問「寫完要等幾多人確認先話完成？」；read concern 問「讀嘅時候只睇幾多人確認咗嘅版本？」。等得越多越安全，但越慢。

    8. Architecture（slide 28）

    Component角色
    Router（mongos）Server instance；接收 query，將 workload 再分配去適當嘅 shards。可以有 1 個或以上（通常喺 app server 旁）
    Config Server（replica set）儲存 cluster 嘅 metadata 同 configuration settings（例如邊個 chunk 喺邊個 shard）
    Shard（replica set）儲存部分 data；2 個或以上，每個 shard 本身係 replica set

    Slide 圖：App Server 上嘅 Routers（mongos）↔ Config Servers（replica set）；Routers 連去 2 個或以上 Shards（各自係 replica set）。

    9. JSON 同 BSON（8b slides 2–12，唔考）

    • MongoDB 用 BSON = binary encoded JSON。JSON 原本用嚟喺 text 表示 JavaScript object，而家係 open standard，跨平台、human-readable、易學、好流行（例如 Binance API 回傳 JSON）。
    • JSON 似 Python dict 但唔同：key 同 string 一定要用雙引號（單引號唔得）。
    • Data types：string、number、object {...}、array [...]、boolean（true / false，case-sensitive）、null（Python 嘅 None）。
    • JSON 唔支援 datetime（可以用 Unix timestamp 等方法）。
    • BSON vs JSON：JSON 只有 text；BSON 可以有 binary data（例如 image）、有 MongoDB 專用 types；但 16 MB document limit，唔建議喺 database 存大 binary data。
    import json
data = {"price": 0.6, "volume": 10, "hold": [9202, 107.3]}
text = json.dumps(data)              # dict → JSON string
obj = json.loads('{ "name": "Wong Wai Kit", "age": 18 }')   # JSON string → dict
obj["name"]                          # 'Wong Wai Kit'

    Slide 9 問題：{"my name": ["Hello", "Kitty"], "neighbor": {"name": "Bob"}} 入面 my name 係 array、neighbor 係 object；而 {"my name": "[ \"Hello\", \"Kitty\" ]", ...} 用 escape character \"，佢哋只係一條 string，睇落似 array / object 但唔係。

    Pickle vs JSON（slide 25）：Pickle 可以存更多種 Python objects，但檔案人睇唔明、只限 Python；bson.Binary 係 MongoDB 喺 Python 嘅 binary wrapper。

    11. Query：find、projection、operators（8b slides 28–39，唔考）

    for x in col.find():              # 好似 SELECT *；find_one 最多回傳一個
    print(x)

# SELECT age FROM COM6002 WHERE name = "Wong Wai Kit"
col.find({"name": "Wong Wai Kit"}, {"_id": 0, "age": 1})   # (query object, projection object)

    Projection 規則（slide 30）：

    • _id 一定會出現，除非明確寫 "_id": 0。
    • 一組非 _id fields 設 1 → 只顯示呢啲（加 _id）。
    • 一組非 _id fields 設 0 → 只排除呢啲。
    • 非 _id fields 有啲 0 有啲 1 → Error。
    Slide 31 projection（data：name、age、sex）結果 fields
    {"age": 0, "sex": 0}_id, name
    {"age": 1, "_id": 1}_id, age
    {"age": 1, "_id": 0}age
    {"age": 1, "sex": 0}Error（1 同 0 混用）
    {"age": 1, "id": 1}（注意係 id 唔係 _id）_id, age（id field 唔存在，所以冇顯示）
    col.find({"name": "Wong Wai Kit"})                  # 只 match top-level name；{"person": {"name": ...}} 唔會 match
col.find({"person.name": "Wong Wai Kit"})           # dot notation：nested field
col.find({"person": {"name": "Wong Wai Kit"}})      # 成個 embedded document 要完全一樣（fields 同次序），多一個 field 都唔 match

col.find({"age": {"$lt": 20}})                      # operators：$eq $gt $gte $in $lt $lte $ne $nin
col.find({"age": {"$in": [18, 20]}})

from bson import Regex
col.find({"name": Regex(".*a.*")})                  # name 包含 "a"（regex，self-study）

col.find().sort("age", 1)                           # 1 = ascending，-1 = descending
col.find({}, {"name": 1, "_id": 0, "age": 1}).sort({"age": -1}).skip(6).limit(3)   # 第 7–9 個 records

my_list = list(col.find())                          # Cursor → list
from pandas import DataFrame
df = DataFrame(list(col.find()))                    # Cursor → DataFrame
    💡 Performance（slides 40–42）

    Chain 嘅寫法唔代表執行次序。find().sort().skip(6).limit(3) 唔係「攞晒所有 documents → project → sort…」，而係（如果有 age index）用 age 嘅 descending index → skip 6 → 攞 3 個 → 只取 name、age → 回傳。比較 list(col.find()) 再喺 Python sort 同 slice：database 做嘅版本快得多，因為只傳 3 個 documents。兩個版本結果都唔一定一樣：Python 版冇 projection（會有晒所有 fields），而且冇 age field 嘅 records 處理方法唔同（Python lambda 當佢 0，MongoDB 當 null）。Rule of thumb：盡量叫 database 做處理，只攞最少嘅 data 返嚟。

    13. Aggregation pipeline（8b slides 48–59，唔考）

    find 只限一個 collection、冇 join。多 collection 或 aggregate query 用 aggregation：一個 pipeline，由多個 stages 組成，上一個 stage 嘅輸出係下一個嘅輸入。

    Stage作用SQL 對應
    $matchFiltering conditionsWHERE（喺 group 之後用就似 HAVING）
    $group分組同計 aggregate statisticsGROUP BY
    $lookup連去另一個 collection 攞資料LEFT (OUTER) JOIN（唔係 INNER JOIN）
    $unwind將 array 拆成多個 documents；常同 $lookup 一齊用—
    $sort排序ORDER BY
    $project揀 fieldsSELECT 嘅 projection list
    result = col.aggregate([
    {"$match": {"profile.Role": {"$ne": "Teacher"}}},        # 1. 唔要 Teacher
    {"$group": {"_id": "$age", "num": {"$count": {}}}},      # 2. 按 age 分組數人數
    {"$match": {"num": {"$gt": 1}}},                         # 3. 只留多過 1 人嘅 age（似 HAVING）
    {"$sort": {"num": -1, "_id": -1}},                       # 4. 人數多到少，再按 age 大到細
])
    • $lookup：{from, localField, foreignField, as}；結果係 list，就算只有一個 match；冇 match 嘅 document 仍然保留（as field 係空 list）。
    • $unwind: "$items"：{"_id": 1, "items": ["apple", "banana"]} → 兩個 documents，items 分別係 "apple"、"banana"。
    • $group：group-by 條件一定放喺 _id；accumulators：$sum、$count、$avg、$min、$max。"_id": None = 全部 documents 一組（例如計總 salary）。
    • $ 符號："$product" 指 field product 嘅值；"product" 只係 string literal。定義 document 結構 / 普通 find query 嘅 field 名唔使 $（例如 find({"status": "active"})）。
    # slide 56：orders 按 product 計總 quantity
db.orders.aggregate([{ "$group": { "_id": "$product", "totalQuantity": { "$sum": "$quantity" } } }])
# → { "_id": "Apple", "totalQuantity": 17 }, { "_id": "Banana", "totalQuantity": 9 }, { "_id": "Orange", "totalQuantity": 8 }

    自我測驗 Self-test

    Q1. 將 RDBMS 嘅 Table、Row、Column 對應到 MongoDB 術語。

    Table → Collection；Row (Record) → Document；Column (Attribute) → Field；Database 兩邊都叫 Database。

    Q2. 乜嘢係 dynamic schema？舉 slide 9 嘅例子。

    同一個 collection 嘅 documents 可以有唔同 fields 同 data types。Amy 嘅 Student ID 係 number（101101），Bob 係 string（"s101102"）；Amy 有 Major、Results，Bob 有 Parents、Brothers。

    Q3. 以下應該 embed 定 reference？(a) 用戶同佢嘅 profile 設定；(b) 學生同選修科目（科目資料好多學生共用）；(c) 社交平台用戶同佢所有 posts。

    (a) Embed：one-to-one、細、通常一齊讀。(b) Reference：many-to-many、child data 被多個 parents 共用。(c) Reference：posts 無上限（unbounded），會超過 16 MB document limit，而且 posts 會被獨立瀏覽。

    Q4. Index 有乜好處同代價？Document 冇 index field 會點？Unique index 有乜效果？

    好處：用 B+ tree 將 search time 降到 \(O(\lg n)\)。代價：額外 storage 同 index maintenance（每次寫入都要更新 index）。冇 index field 嘅 document 當作 null。Unique index 會 reject 重複值。

    Q5. 描述 ObjectId 嘅組成。點解佢可以按時間排序？

    12 bytes：4-byte timestamp + 5-byte random value + 3-byte incrementing counter。開頭係 timestamp，所以按 _id 排序大致等於按建立時間排序。ObjectId 睇落似 string 但唔係 string。

    Q6. IM app 要 (a) 平均分散 storage load；(b) 快速讀取某用戶某月嘅 messages。各用乜 sharding？

    (a) Hashed sharding：hash 後分佈平均。(b) Ranged sharding by (account, datetime)：同一用戶同一段時間嘅 messages 喺同一 chunk，range query 只讀少數 chunks。

    Q7. Replica set 入面，default 情況下 reads 去邊？Secondary 有乜用？Primary 壞咗點算？

    Reads 同 writes 都去 primary（workload 唔分擔）；可以設定 read from secondary（例如 nearest）。Secondaries 用嚟 backup 同 recovery。Primary 壞咗，剩低嘅 nodes 經 heartbeat 發現，elect 新 primary。

    Q8. 比較 w: 1 同 w: "majority"。Mission-critical data 應該點設？

    w:1：primary apply 就回覆，最快，但 primary 喺 replicate 前壞咗會 lost data。w:"majority"：majority data-bearing members apply 先回覆，最 durable、可 survive failover，但 latency 高。Mission-critical：w: "majority" + j: true（寫入 journal）。

    Q9. Read concern local 同 majority 有乜分別？

    local（default）：回傳當前 member 嘅 data，可能未包括其他 members 嘅 writes，但最快。majority：只回傳 majority acknowledge 咗嘅 data，保證 durable。

    Q10. Sharded cluster 入面 router 同 config server 各做乜？

    Router（mongos）：接收 query，分配去相關 shards。Config server（replica set）：儲存 cluster 嘅 metadata 同 configuration（例如 data 分佈喺邊個 shard）。

    Q11.（8b，唔考）find({}, {"age": 1, "sex": 0}) 會點？$lookup 似 SQL 邊種 join？

    Error：非 _id fields 唔可以 0 同 1 混用。$lookup 等於 LEFT OUTER JOIN，冇 match 嘅 document 仍然保留，結果 field 係 list。

    一頁總結 Cheat sheet

    ⭐ 考前速記
    • MongoDB：document-based、Top-1 NoSQL、dynamic schema、BASE（可設定 ACID，有 overhead）、horizontal scalability、programming friendly（唔使學 SQL）。
    • Database → Collection（Table）→ Document（Row）→ Field（Column）。Hierarchical / nested documents。
    • Embed：parent context、細 & bounded、1:1、1:N 專屬、fast reads。Reference：獨立睇、M:N、共用、大 / unbounded。Max document 16 MB。
    • Index：B+ tree，\(O(\lg n)\)；asc / desc / 2dsphere（R-tree）/ text；missing → null key（non-sparse）；unique 拒絕重複；代價 = storage + maintenance。
    • _id：mandatory、unique（sharded 而唔係 shard key → 每 shard 內）、ObjectId 12 bytes = 4 timestamp + 5 random + 3 counter；chronological；唔係 string；可自訂。
    • Sharding = horizontal fragmentation；shard key + strategy；hashed（平均分散）vs ranged（range query）；IM 例子：storage → hashed；按月讀 → ranged (account, datetime)。
    • Replica set：redundancy & availability，似 Raft；heartbeat；default 讀寫都去 primary；secondaries = backup & recovery；primary 壞 → election。
    • Write concern（latency vs durability）：w:1 最快有 lost 風險；w:"majority" 最 durable；j:true journal；best = majority + j。Read concern：local（最快）vs majority（durable）。
    • Architecture：Router（mongos）分派 query；Config servers 存 metadata；Shards 各自係 replica set。
